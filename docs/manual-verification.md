# 吉日タイマー 手動検証手順書

自動テスト(`node --test "tests/*.test.mjs"`)では再現できない、実ブラウザ・実機でしか確認できない項目をまとめる。

## 事前準備

```bash
cd /path/to/ActionTimer
python3 -m http.server 8000
# ブラウザで http://localhost:8000 を開く
```

時間経過の検証には、開発者ツールのコンソールで以下のスニペットを使う(`HOURS` を変えて経過時間を作る):

```js
// 経過時間を偽装した項目を注入する(例: 71時間経過 = 残り1時間)
const HOURS = 71;
const key = "kichijitsu-timer-v1";
const data = JSON.parse(localStorage.getItem(key)) ?? { pending: [], started: [] };
data.pending.push({ id: crypto.randomUUID(), title: `${HOURS}時間経過テスト`,
  createdAt: Date.now() - HOURS * 3600 * 1000 });
localStorage.setItem(key, JSON.stringify(data));
location.reload();
```

検証後の後始末: `localStorage.removeItem("kichijitsu-timer-v1"); location.reload();`

## 正常系検証

| # | 検証項目 | 手順 | 期待結果 |
|---|---------|------|---------|
| 1 | 点火 | テキストを入力して「点火」 | 帳票カードが追加され、線香が満タン・火種が右辺中央で点滅 |
| 2 | 再読込後の保持 | 点火後にページを再読込 | 項目が残り、残り時間が経過分だけ減っている |
| 3 | 着手フロー | 「着手した」→「何をやった?」に記入→「記録」 | カードが「始めた」リストへ移動し、やったことが時刻付きで表示 |
| 4 | 追記 | 始めたカードの「やったことを追記」に記入 | ログの末尾に時刻付きで追加される |
| 5 | 着手の必須入力 | 「着手した」→ 空欄のまま「記録」 | ブラウザの必須入力警告が出て移動しない |
| 6 | 線香の燃え方 | スニペットで36時間経過の項目を注入 | 線香が右辺中央→上辺→左辺の途中まで灰(点線)になり、火種が燃焼点にある |

## 境界値検証

| # | 検証項目 | 手順 | 期待結果 |
|---|---------|------|---------|
| 1 | タイトル最大長 | 100文字を超えて入力し続ける | inputのmaxlengthにより100文字で打ち止め |
| 2 | 残り12時間の警告色 | スニペットで `HOURS = 60.001` を注入 | 残り時間が赤色・太字になる |
| 3 | 残り12時間ちょうど | `HOURS = 60` を注入 | 警告色にならない(境界は含まない) |
| 4 | 燃え尽きの瞬間 | `HOURS = 71.999` を注入し、燃え尽きるまで画面を開いたまま待つ | 「燃え尽きました…」表示→燃え落ちるアニメーション→カード消滅。再読込しても復活しない |
| 5 | 起動時に既に期限切れ | `HOURS = 100` を注入 | 起動直後に燃え尽きアニメーション後に消える |
| 6 | 端末時計の巻き戻し | 点火後、OSの時計を1時間戻す | 線香が満タン側へ戻る(仕様: 対策しない)。クラッシュしないこと |
| 7 | 大量項目 | スニペットをループで100件注入 | 一覧がスクロールでき、毎秒更新でカクつかない |
| 8 | タイムゾーン変更 | 点火後、OSのタイムゾーンを変更して再読込 | 表示時刻はローカル時刻に追従。残り時間は変わらない(エポックミリ秒基準) |
| 9 | 画面幅の境界 | ウィンドウを320px幅まで縮める / 横向きスマホ | レイアウト崩れ・横スクロールが発生しない |

## 異常系検証

| # | 検証項目 | 手順 | 期待結果 |
|---|---------|------|---------|
| 1 | 破損データで起動 | コンソールで `localStorage.setItem("kichijitsu-timer-v1", "{{{")` → 再読込 | 空の初期状態で起動。コンソールに日本語のエラーログ(キー名と対処を含む) |
| 2 | 保存失敗(プライベートモード) | SafariのプライベートウィンドウやStorage容量を絞った状態で点火 | 画面上部に赤いバナー「保存に失敗しました。…」が表示され、操作は継続できる |
| 3 | バナーの自動回復 | #2 の後、通常モードで開き直して点火 | バナーが消え、正常に保存される |
| 4 | オフライン起動(PWA) | 一度開いた後、開発者ツールのNetworkで「Offline」にして再読込 | Service Workerのキャッシュからアプリが開き、操作できる |
| 5 | オフライン+未キャッシュ | Offlineのまま `http://localhost:8000/nai.html` を開く | 日本語の503メッセージ「オフラインのため読み込めません。…」 |
| 6 | SWキャッシュ更新 | `sw.js` の `CACHE_VERSION` を上げて配信→再読込を2回 | 2回目の再読込で新しいアセットが反映される |
| 7 | 2タブ同時操作 | 2つのタブで開き、両方から点火 | 後から操作したタブの内容で上書きされる(既知の制限。クラッシュしないこと) |
| 8 | タブ放置で日付跨ぎ | タブを開いたままPCをスリープ→翌日復帰 | 復帰後の描画が実時間に追いつく(残り時間がワープして正しい値になる) |
| 9 | XSS | タイトルに `<img src=x onerror=alert(1)>` を入力して点火 | 文字列のまま表示され、スクリプトは実行されない |
| 10 | ホーム画面追加(iOS) | SafariでA2HS→起動 | スタンドアロンで起動する。アイコンが粗い場合はKnown Debt(PNG未生成)による |

## 対象外と判断した観点

テスト方針の網羅項目のうち、このアプリの構成(ブラウザ内完結・サーバーなし・ファイルI/Oなし・依存なし)により対象外としたもの:

| 観点 | 対象外の理由 |
|------|-------------|
| ファイルの境界・ファイルシステム異常 | ファイルI/Oが存在しない(永続化はlocalStorageのみ) |
| 外部サービス異常(APIキー・429・5xx等) | 外部API呼び出しが存在しない |
| 環境異常(環境変数・依存パッケージ) | 環境変数・依存パッケージを使用しない |
| プロセスの並行・強制終了・ゾンビ化 | プロセスを生成しない。並行性はタブ間競合として異常系#7で検証 |
| 文字コード混在・BOM | 入力はブラウザ経由で常にUTF-16(JS文字列)。ファイル読込がない |
| 無効な日付(2025-13-01等) | 日付は常に `Date.now()` のエポックミリ秒で生成され、文字列の日付入力が存在しない |
| 循環参照 | UIからは作れない。発生時はsaveStateのcatch(保存失敗バナー)で検知される |
