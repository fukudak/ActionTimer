# 設計

吉日タイマーの技術構成に関する判断を記録する。
解決する問題・不変条件の要約は [`../CLAUDE.md`](../CLAUDE.md) を参照。

## アーキテクチャ: PWA + Vanilla JS + localStorage

**状態:** Accepted

### 決定
Vanilla JS 単一ページ PWA とし、永続化は localStorage(キー `kichijitsu-timer-v1`)のみとする。実行時のバンドル・変換は行わず、配信時だけ `npm run build` で `index.html`、`about.html`、アセットを `dist/` にコピーする。

### 背景
72時間の法則に基づく「吉日タイマー」を新規開発するにあたり、プラットフォーム選定が必要だった。
登録した項目が72時間で燃え尽きる様子を可視化する個人用の小さなアプリで、
リマインド通知は不要(ユーザー確認済み: PWA前提のWebアプリ)。

### 根拠
- 通知不要のため、ネイティブアプリ(Flutter)の主な利点が消える
- PWAならスマホのホーム画面に置けて、オフラインでも開ける
- 機能が小さく(登録・表示・移動の3操作)、フレームワークや外部依存は過剰
- サーバー・アカウント不要で、データは端末内で完結する

### 却下した代替案

| 代替案 | 却下理由 |
|--------|----------|
| Flutter (iOS/Android) | 通知不要のため利点が薄く、開発・ビルド・配布コストが過大 |
| React/Vue + ビルド工程 | 3操作のアプリに対して依存とビルドの維持コストが見合わない |
| IndexedDB | データ量が極小(数十件のテキスト)で localStorage で十分 |

### 結果
- 端末・ブラウザをまたいだ自動同期はできない(許容済み)
- 配信物を変えるたびに Service Worker のキャッシュバージョン管理が必要 → [運用](./operations.md)
- 自動テストも「依存なし」方針に合わせて Node 組み込みランナーを採用 → [テスト](./testing.md)
- 本番画面は明るい和風の一行入力UIを採用し、デザインモック固有の履歴・編集・ソート等は採用しない

### 見直し条件
- リマインド通知が必要になったとき(Push対応のためサーバーかネイティブ化を再検討)
- 複数端末での自動同期が必要になったとき
