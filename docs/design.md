# 設計

吉日タイマーの技術構成に関する判断を記録する。
解決する問題・不変条件の要約は [`../CLAUDE.md`](../CLAUDE.md) を参照。

## アーキテクチャ: PWA + Vanilla JS + localStorage

**状態:** Accepted

### 決定
Vanilla JS 単一ページ PWA とし、永続化は localStorage(キー `kichijitsu-timer-v1`)のみとする。実行時のバンドル・変換は行わず、配信時だけ `npm run build` で `index.html`、`about.html`、アセットを `dist/` にコピーする。

### 背景
72時間の法則に基づく「吉日タイマー」を新規開発するにあたり、プラットフォーム選定が必要だった。
登録した項目が72時間で燃え尽きる様子を可視化する個人用の小さなアプリで、
リマインド通知は不要(ユーザー確認済み: PWA前提のWebアプリ)。

### 根拠
- 通知不要のため、ネイティブアプリ(Flutter)の主な利点が消える
- PWAならスマホのホーム画面に置けて、オフラインでも開ける
- 機能が小さく(登録・表示・移動の3操作)、フレームワークや外部依存は過剰
- サーバー・アカウント不要で、データは端末内で完結する

### 却下した代替案

| 代替案 | 却下理由 |
|--------|----------|
| Flutter (iOS/Android) | 通知不要のため利点が薄く、開発・ビルド・配布コストが過大 |
| React/Vue + ビルド工程 | 3操作のアプリに対して依存とビルドの維持コストが見合わない |
| IndexedDB | データ量が極小(数十件のテキスト)で localStorage で十分 |

### 結果
- 端末・ブラウザをまたいだ自動同期はできない(許容済み)
- 配信物を変えるたびに Service Worker のキャッシュバージョン管理が必要 → [運用](./operations.md)
- 自動テストも「依存なし」方針に合わせて Node 組み込みランナーを採用 → [テスト](./testing.md)
- 本番画面は明るい和風の一行入力UIを採用する。デザインモック固有の編集・並び替え・複数ページ切替は採用しないが、着手履歴と着手率は本番機能として採用する(→ 次項)

### 見直し条件
- リマインド通知が必要になったとき(Push対応のためサーバーかネイティブ化を再検討)
- 複数端末での自動同期が必要になったとき

## 着手履歴と着手率の採用

**状態:** Accepted

### 決定
着手した項目は削除前に着手履歴(タイトル・点火日時・着手日時)へ記録する。不発弾セクションの
表示名は「不発弾」から「燃え尽きた」に変更する。着手率は `着手件数 / (着手件数 + 燃え尽きた件数)`
で算出し、履歴セクションに平均着手時間とあわせて表示する。

### 背景
一度「デザインモック固有の履歴機能は本番採用しない」と判断したが、着手ペースを振り返れないのは
実用上不便との判断で方針を変更した。

### 根拠
- 着手率・平均着手時間は行動の振り返りに直結し、「通知では急かさない」という設計思想とも両立する
- 履歴はタイトル・日時のみで、追加入力(理由・メモ等)は求めない。既存の「追加入力なしで消える」体験は維持する
- 「不発弾」は着手を逃した項目という否定的な響きが強いため、状態の呼称を「燃え尽きた」に統一する

### 却下した代替案

| 代替案 | 却下理由 |
|--------|----------|
| 履歴に理由・メモの入力を必須化 | 追加入力なしで即座に消えるという体験を損なう |
| 履歴を上限件数で自動削除 | 個人用アプリでデータ量は小さく、上限管理の複雑さに見合わない |
| 編集・並び替え・複数ページ切替の再導入 | 履歴とは独立した論点であり、単一画面の一行UIという方針とは相性が悪いため見送る |

### 結果
- CLAUDE.md の不変条件を「履歴を残さず削除」から「着手履歴に記録してから削除」へ更新した
- 保存形式に `history` 配列を追加し、旧データ(`history` なし)は空配列として正規化する
- `tests/test_ui_contract.test.mjs` の「モック機能除外」テストを、履歴・着手率を許可する内容に更新した

### 見直し条件
- 履歴データが肥大化しパフォーマンスに影響したとき(上限・アーカイブを再検討)

## 着手率表示の撤去、着手ボタンへの確認ダイアログ追加

**状態:** Accepted

### 決定
履歴セクションから着手率の表示を撤去する(平均着手時間のみ残す)。着手ボタン押下時に
`confirm()` で意思確認を行い、OKなら着手・キャンセルなら何もしない。

### 背景
着手率表示は誤操作防止の役に立たず、着手ボタンは押した瞬間に確定的に状態を変える
(取り消し不可)ため、ユーザーからの明示的な指示で見直した。

### 根拠
- 着手率は履歴を振り返る指標だったが、優先度は低いと判断された
- 着手は不可逆な操作であり、削除操作(`confirm`で確認済み)と同様に誤操作防止が必要

### 却下した代替案

| 代替案 | 却下理由 |
|--------|----------|
| 着手率のみ非表示にし、内部計算は残す | 表示しない値を計算し続けるのは無駄なコードになる |

### 結果
- `app.js` の `renderHistory` から着手率(`rate`・`resolvedCount`)の算出と表示を削除した
- `app.js` の着手ボタンのクリックハンドラに `confirm()` を追加した
- `about.html` の履歴セクション説明文からも着手率の表示例を削除した
- `tests/test_ui_contract.test.mjs` と `tests/test_lp_contract.test.mjs` を実装に合わせて更新した

### 見直し条件
- 着手率の需要が再び高まったとき(再導入を検討)
